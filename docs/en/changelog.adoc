== Documentation change history

// Documentation revisions (MAJOR.MINOR.REVISION). Format changes: see CHANGELOG.adoc in the specification.
=== 2.0.0

* New documentation of the `cz-ndic_d2-common` format version 2.0 (DATEX II 3.7); replaces the
  documentation of the cz-ndic_d2-common-v1.2 format (DATEX II 2.3).
* Changes compared to version 1.2 (DATEX II 2.3):
** The format has been migrated to the DATEX II 3.7 model without national extensions. The `d2LogicalModel`
   and `exchange` envelopes are not used; the root is `d2:payload`, the format is identified by the
   `profileName` and `profileVersion` attributes.
** `safetyRelatedMessage` is part of the model (formerly a national extension).
** The national location extensions (`linearExtension`, `globalNetworkLinear`, `openlrExtendedLinear`) were
   replaced by elements of the 3.7 model: OpenLR in `openlrLinear`, Global Network sections in
   `linearWithinLinearElement` with `LinearElementByCode`.
** The start and end of a GN location (`startPoint`, `endPoint` in S-JTSK) are replaced by the location path
   in ETRS89 (`gmlLineString`); GN edge sections use percentages.
** New mandatory element `alertCAffectedDirection`.
** Neither point locations (`PointLocation`) nor area locations (`AreaLocation`) are used; a point-like
   place is a short linear section, an area a list of linear sections.
** The supplementary positional description (`supplementaryPositionalDescription`) follows the structure of
   model 3.7: the carriageway and lanes (previously `affectedCarriagewayAndLanes`) are in `carriageway` with
   `lane/laneUsage`, the description of the place (previously `locationDescriptor`) in
   `infrastructureDescriptor` or `geographicDescriptor`.
** `trafficConstrictionType` is given directly in the record (previously in `impact`), only in records that
   have it in model 3.7 (accidents, obstructions, activities, conditions, abnormal traffic); for roadworks the
   extent of the restriction is expressed by the `RoadOrCarriagewayOrLaneManagement` record and `impact`.
** A location is not described by one linear location over several roads: `SingleRoadLinearLocation` is a
   contiguous section of one road with at most one `alertCLinear`, a contiguous route over several roads is
   `ItineraryByIndexedLocations` and a non-contiguous or branching location `LocationGroupByList`.
** Enumeration values removed by the DATEX II 3 model are expressed by a general value with an additional
   element – e.g. a bus accident is `accidentType` = `accident` with
   `groupOfVehiclesInvolved/vehicleCharacteristics/vehicleType` = `bus`, an overturned vehicle `accident`
   with `groupOfVehiclesInvolved/vehicleStatus` = `overturned`, a broken-down lorry
   `vehicleObstructionType` = `brokenDownVehicle` with `vehicleType` = `lorry`, a slow road maintenance
   vehicle `slowVehicle` with `vehicleUsage` = `roadMaintenanceOrConstruction`.
** Wind speed is given in m/s (previously km/h according to the ALERT-C message).
** Not used: the description of the data source `feedDescription` (the source is identified by `feedType`),
   the situation summary record `situationSummary` (a summary would need its own location, validity and
   mandatory type elements; comments remain in the individual records), the route destination
   `routeDestination` and recurring validity intervals other than a daily time period
   (`recurringTimePeriodOfDay`).
** Car park occupancy (`CarParks` records) is not part of the format; it is provided by the separate format
   `cz-ndic_d2-city-parking-status`.
** Warnings generated by road weather stations (with a reference to the station section) are not part of the
   format; they are provided by the format `cz-ndic_d2-weather`. Manually reported weather events remain in this format.
** The profile is narrowed to the elements and enumeration values that NDIC publishes or that ALERT-C messages
   fill; ALERT-C values removed from the profile are expressed by a more general value (e.g. a tennis tournament
   `sportsMeeting`).
* Origin of the data:
** Most events originate from ALERT-C messages (event codes and quantifiers according to <<ISO14819-2>>).
** The directionality of an event (`alertCAffectedDirection`) follows the directionality in the ALERT-C event list <<ISO14819-2>>.
** Diversions (`ReroutingManagement`) and temporary speed limits (`SpeedManagement.temporarySpeedLimit`) are
   kept in the profile for future event sources.
